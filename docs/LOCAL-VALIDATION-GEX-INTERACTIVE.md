# Local Validation: GEX-SPY Interactive Host E2E

> **Phase 3 Definition of Done evidence.** Real interactive host (Claude Code) → real GaleCore GEX-SPY → versioned assets → structured interpretation → deterministic assurance → SUCCESS + fail-closed negatives.

## Prerequisites

1. **GaleCore** (.NET) running on `http://localhost:7001` with Tastytrade session active
2. **GaleCore-AI** (Python) dependencies installed: `pip install -e ".[dev]"`
3. An interactive host capable of reading facts and producing a `GexInterpretation` JSON (Claude Code, Claude Work, or equivalent)

## Step 1 — Prepare snapshot

Fetch live GEX data from GaleCore and produce an immutable identified snapshot:

```powershell
$env:GALECORE_BASE_URL = "http://localhost:7001"
$env:GALECORE_API_KEY = "<your GaleCore ApiKey from user-secrets>"
$env:ALLOW_UNKNOWN_FRESHNESS = "true"
$env:MAX_STALENESS_SECONDS = "3600"
python -B -m galecore_ai.adapters.cli prepare --symbol SPY
```

Output: `PreparedAnalysisView` JSON with `run_id`, `facts`, `facts_hash`, timestamps, and `effective_assets` (hashes of loaded YAML definitions). The authoritative snapshot stays in the internal store — the host receives only a read-only view.

**Rules (Increment 4 contract):**
- `regime` is `positive_gamma` or `negative_gamma` by the sign of `net_gex`; `near_zero` is always rejected (GaleCore publishes call/put GEX and net GEX in incompatible scales).
- `observations` and `implications` are qualitative: **no digits**.
- Interpretive numbers go in `quantitative_claims` as `{metric, value, unit}`; `metric` ∈ `net_gex | spot | zero_gamma_level | call_wall | put_wall`, `unit` = `billion_usd` for `net_gex` and `usd` otherwise, `value` exactly equal to the fact (no rounding, no rescaling). `quantitative_claims`, `evidence` and `limitations` are required and non-empty.
- Every `evidence.fact_path` must resolve to a scalar fact; a number inside an evidence claim must equal that fact. The validator does not verify the prose semantically.
- No explicit trading recommendations (buy/sell/hold/accumulate… in English or Spanish).

## Step 3 — Accept interpretation

Send the `run_id` (from prepare output) and interpretation to the accept command. The snapshot is **not** sent back — it is recovered internally from the store by `run_id`:

```powershell
@"
{
  "run_id": "<run_id from prepare output>",
  "interpretation": <your interpretation JSON>,
  "host_provider": "claude-code",
  "host_model": "claude-opus-5"
}
"@ | python -B -m galecore_ai.adapters.cli accept
```

Or programmatically:

```python
from galecore_ai.adapters.snapshot_store import FileSnapshotStore
from galecore_ai.application.accept_interpretation import accept_gex_interpretation
from galecore_ai.contracts.prepared_analysis import AcceptanceRequest

store = FileSnapshotStore()
request = AcceptanceRequest(
    run_id="<run_id from prepare>",
    interpretation=interpretation_dict,
    host_provider="claude-code",
    host_model="claude-opus-5",
)
result = accept_gex_interpretation(
    store=store,
    request=request,
    allow_unknown_freshness=True,
)
```

## What this proves and what it does not

**Proves:**
- The prepare/accept boundary works with real GaleCore data
- Deterministic assurance catches invented numbers, ungrounded evidence, sign contradictions, malformed output, integrity violations, and freshness expiration
- The accept path records the host's declaration (`HOST_DECLARED:claude-code`); it does not verify host identity or that a model was executed. The P1 interpretation was authored in a Claude Code session reading the prepared view; that authorship is declared, not proven
- Cognitive assets (agent, skill, protocol, conventions) are loaded from canonical YAML with content hashes in the snapshot

**Does not prove:**
- Model quality or specialization (`validator_called_model=false`, `host_model_execution=HOST_DECLARED` — the validator cannot verify the host called a model)
- That the host obeys the cognitive assets (hash proves what was loaded, not compliance)
- Semantic entailment of free-text prose
- Near-zero regime: never accepted. GaleCore publishes call_gex/put_gex and net_gex in incompatible scales, so the validator rejects `near_zero` fail-closed; the YAML threshold is preserved but inert
- Semantic entailment of qualitative evidence claims (EvidenceRef proves the path resolves, not the meaning)
- Persistent trace storage (store is ephemeral in `$TEMP`)
- That `from_cache: false` means data is live (GaleCore internal caching is opaque)
- Filesystem isolation of the snapshot store (a process with the same OS user can modify the store directly; the store is an MVP for a cooperative host, not a security boundary)

## Configuration

| Variable | Default | Description |
|---|---|---|
| `GALECORE_BASE_URL` | `http://localhost:7001` | GaleCore API URL |
| `GALECORE_API_KEY` | — | Must match GaleCore user-secrets `ApiKey` |
| `LOCAL_VALIDATION` | `true` | Restrict to localhost |
| `MAX_STALENESS_SECONDS` | `300` | Max age before rejection |
| `ALLOW_UNKNOWN_FRESHNESS` | `false` | Accept data without timestamp |
| `GALECORE_TIMEOUT_SECONDS` | `120` | HTTP timeout for prepare |
| `SNAPSHOT_TTL_SECONDS` | `3600` | Max snapshot age in store before expiry |
