# Local validation — daily regime with an evaluable record (interactive host)

Work item: `docs/engineering/work-items/GC-AI-0002-phase4-host-harness-evaluable-record.md`.
Evidence of a real run: `docs/evidence/gc-ai-0002-e2e/` (generated by `tools/e2e_regime_cases.py`).

This guide covers the Phase 4 loop from an interactive host (Claude Code): ask for data → ask for
an interpretation → ask for persistence → leave an evaluable record → query it later. The
autonomous runtime is not involved; the validator never calls a model.

## 1. Prerequisites

- GaleCore API running on `http://localhost:5000` with Tastytrade market data available.
- The GaleCore ApiKey from `dotnet user-secrets` (project `DataFeed.Api`). It is passed as
  `GALECORE_API_KEY` and is never written to records, evidence, fixtures or docs.
- The workspace knowledge base `<workspace>/knowledge/` (must exist; `GALECORE_KNOWLEDGE_DIR`
  overrides it) or `GALECORE_RECORDS_DIR` pointing at a records directory. Until GC-AI-0005
  (2026-09-23) the default was `../GaleCore/research/regime`; the records were moved from there.

```bash
export GALECORE_BASE_URL=http://localhost:5000
export GALECORE_API_KEY=<ApiKey>
export ALLOW_UNKNOWN_FRESHNESS=true    # required: PutSkew publishes no as-of timestamp → snapshot freshness is UNKNOWN at best
export MAX_STALENESS_SECONDS=36000     # daily records are produced AFTER the cash session (16:30–20:00 ET, owner decision F-2); the last prints are then minutes to a few hours old
export GALECORE_TIMEOUT_SECONDS=300    # a cold GEX computation can exceed 120 s
```

## 2. Sources and facts

`prepare --skill regime` invokes four capabilities concurrently and fails closed if any one is
missing, malformed or stale (there is no partial regime):

| Source key | Capability | GaleCore endpoint | Timestamp | Facts produced |
|---|---|---|---|---|
| `gex` | `compute.gex_analysis` (COMPUTE) | `GET /App/Gex/Analysis` | `timestamp` | `net_gex`, `call_gex`, `put_gex`, `spot`, `zero_gamma_level`, `call_wall`, `put_wall`, `coverage_pct` |
| `put_skew` | `compute.put_skew` (COMPUTE) | `GET /App.Analytics/PutSkew` | none → `UNKNOWN` | `put_skew_ratio` (=`putSkew25d`), `atm_iv`, `put_wing_iv` (=`put25DeltaIV`), `put_skew_dte`, `put_skew_expiration`, `put_skew_level_ok`, `put_skew_level_threshold` |
| `vix` | `market_data.trade` (PURE_QUERY) | `GET /Data/Tastytrade/MarketData/Trade?symbol=VIX` | `time` (epoch ms) | `vix` |
| `vvix` | `market_data.trade` (PURE_QUERY) | `GET /Data/Tastytrade/MarketData/Trade?symbol=VVIX` | `time` (epoch ms) | `vvix` |

`facts.sources.<key>` records capability, endpoint, provenance (`GALECORE_VERIFIED`),
`market_data_as_of`, `freshness_basis` (`galecore_timestamp` | `none`), `freshness_status` and
`response_received_at`. Snapshot-level `market_data_as_of` is the oldest declared timestamp;
`freshness_status` is the worst per-source status (STALE > UNKNOWN > VALID).

Metric and fact names carry no digits on purpose (`put_skew_ratio`, not `put_skew_25d`): the
`no_invented_numbers` guardrail scans the serialized interpretation, and a digit inside a key
would read as an invented number.

## 3. The interpretation (host-authored)

`RegimeInterpretation` (`src/galecore_ai/contracts/regime_analysis.py`):

- **gamma_regime**: `positive_gamma` if `net_gex > 0`, `negative_gamma` if `< 0`; `near_zero` is
  always rejected (same rule and reason as the GEX skill).
- **tail_pricing**: `calm` iff `facts.put_skew_level_ok` is `true`, `elevated` iff `false`. The
  threshold is GaleCore's (`put_skew_level_threshold`); GaleCore-AI does not decide it.
- **observations** / **implications**: qualitative prose, no digits. Descriptive positioning
  ("short gamma", "short-gamma side", "corto-gamma") is not a directive; buy/sell/hold-style
  directives in English or Spanish are rejected (pattern-based; novel phrasings may bypass).
- **quantitative_claims** (≥1): `{metric, value, unit}`; `value` must equal the fact exactly.

  | metric | unit |
  |---|---|
  | `net_gex` | `billion_usd` |
  | `spot`, `zero_gamma_level`, `call_wall`, `put_wall` | `usd` |
  | `put_skew_ratio` | `ratio` |
  | `atm_iv`, `put_wing_iv` | `iv_decimal` (0.1435 = 14.35 %) |
  | `vix`, `vvix` | `index_points` |

  `call_gex`, `put_gex`, thresholds and DTEs cannot be claimed.
- **evidence** (≥1): `{fact_path, claim}`; the path must resolve to an available scalar
  (`facts.put_skew_level_ok` is a valid boolean target). Entailment of the prose is **not**
  checked: read the facts before writing (e.g. whether `spot` is below or above
  `zero_gamma_level`).
- **limitations** (≥1).
- Do not compare with earlier sessions from memory: only this run's facts exist for the validator.
  Comparisons are legitimate only against records read through `query`, and must be stated in
  limitations.

Structural checks run on the parsed model: `gex_regime_sign`, `tail_pricing_level`,
`quantitative_claims_valid`. Text guardrails: `no_invented_numbers` and `facts_match_source`
(exact numeric equality — 17.715 for 17.71 is an invented number), `no_trading_recommendation`
(bounded pattern set EN/ES, incl. "bullish/bearish position", "posición alcista/bajista"; novel
phrasings are a declared limitation per the owner's Phase 3 decision), `no_numbers_in_prose`.
All are recorded in the trace, after `snapshot_integrity` (facts, conventions and the
`snapshot_hash` that binds skill, freshness window, assets and capabilities to the snapshot).

## 4. The loop

```bash
# 1. prepare
python -B -m galecore_ai.adapters.cli prepare --symbol SPY --skill regime > view.json

# 2. interpret (host) → interpretation.json

# 3. accept and record (record written only on SUCCESS)
python - <<'EOF' > request.json
import json; v=json.load(open("view.json")); i=json.load(open("interpretation.json"))
print(json.dumps({"run_id": v["run_id"], "interpretation": i, "host_provider": "claude-code", "host_model": "claude-opus-5"}))
EOF
python -B -m galecore_ai.adapters.cli accept --record --prompt "Analizá el régimen de hoy de SPY y guardalo" < request.json

# 4. later: outcome (facts fetched now; a STALE source is rejected like in prepare) and human review
python -B -m galecore_ai.adapters.cli record outcome --symbol SPY --date 2026-09-16 --run-id <run_id>
python -B -m galecore_ai.adapters.cli record review  --symbol SPY --date 2026-09-16 --run-id <run_id> --verdict partial --comment "..."

# 5. query (no model call)
python -B -m galecore_ai.adapters.cli query --symbol SPY --since 2026-09-09
```

Exit codes: `0` SUCCESS · `1` prepare / record / internal failure · `2` INSUFFICIENT_DATA ·
`3` VALIDATION_ERROR, argument errors, and `query` when any record is `INTEGRITY_FAILED`.

`accept --record` adds `record` to the output: `RECORDED {path, date, entry_id, entry_hash}`,
`NOT_RECORDED` (result was not SUCCESS) or `RECORD_FAILED` (SUCCESS but the file could not be
written; exit 1). `--record` without `--prompt` is an argument error (exit 3).

## 5. The record

Path: `<records_dir>/<SYMBOL>/<YYYY-MM-DD>.md`, where `records_dir` is `GALECORE_RECORDS_DIR` or
`<workspace>/knowledge/regime` (before GC-AI-0005: `../GaleCore/research/regime`), and the date is `prepared_at` in the convention timezone
(`America/New_York`, from `trading-defaults.yaml`). One file per symbol and trading day; a second
run the same day appends an entry; the same `run_id` cannot be recorded twice.

The file is Markdown whose **YAML frontmatter is the authoritative document** (`schema_version`,
`symbol`, `date`, `entries`); a human-readable summary per entry follows and is derived, never
parsed back. Each entry (`contracts/regime_record.py`) holds:

| Field | Content | Provenance |
|---|---|---|
| `request` | prompt, symbol, skill_id | host |
| `snapshot` | run_id, prepared_at, facts_hash, conventions_hash, market_data_as_of, freshness_status | validator |
| `facts` | the hashed facts | `GALECORE_VERIFIED` |
| `effective_assets` | agent / skill / protocol / convention ids, versions, hashes | validator |
| `host` | provider, model | `HOST_DECLARED` |
| `accepted_payload` | the exact accepted interpretation | validator |
| `trace` | trace_id, accepted_at, facts_provenance, guardrails, capabilities | validator |
| `entry_hash` | sha256 over everything above (canonical JSON) | validator |
| `outcomes[]` | later facts, their hash, capabilities, `GALECORE_VERIFIED` | appended by `record outcome` |
| `human_reviews[]` | reviewed_at, verdict `agree|partial|disagree`, comment | appended by `record review` |

Integrity: on every read the store parses the frontmatter (first line to the first `---` at
column 0 — PyYAML never emits one inside a scalar, and `save` re-parses the rendered text before
replacing the file), validates it against the record contract (unknown `schema_version` fails),
recomputes `entry_hash`, `facts_hash` and each outcome's `facts_hash`, and checks that symbol/date
match the file location; any problem makes the file `INTEGRITY_FAILED`. `query` reports it (never skips it) and exits 3; `record outcome` / `record
review` refuse to modify it; `accept --record` refuses to append to it. The record is a
cooperative local file: hashes detect edits, they do not prevent them. No secrets, raw logs or
chain-of-thought are stored.

## 6. Reproducible E2E

```bash
python tools/e2e_regime_cases.py --phase prepare --out docs/evidence/gc-ai-0002-e2e
# author docs/evidence/gc-ai-0002-e2e/host-interpretation.json from view.json
python tools/e2e_regime_cases.py --phase run --out docs/evidence/gc-ai-0002-e2e \
    --reuse-view docs/evidence/gc-ai-0002-e2e/view.json \
    --interpretation docs/evidence/gc-ai-0002-e2e/host-interpretation.json
```

Every record the runner writes goes to temporary directories deleted at the end; the runner never
touches the real records directory (`knowledge/regime`, formerly `GaleCore/research/regime`). P3 is a runner-authored review (mechanics only). Artifacts are
sanitized (first-line errors, `<repo>/<tmp>/<home>` paths). Real records come only from genuine
host runs; the first one is documented in `docs/evidence/gc-ai-0002-manual-host-run/`.

## 7. Known limits

- The regime snapshot can never be `VALID` while PutSkew publishes no timestamp; the host must run
  with `ALLOW_UNKNOWN_FRESHNESS=true`. Per-source status remains visible in `facts.sources`.
- **Policy (owner decision F-2, 2026-09-19):** daily records are produced only after the cash
  session (16:30–20:00 ET) with `MAX_STALENESS_SECONDS=36000`. Pre-market or weekend runs are not
  part of the series: VVIX has no pre-market print and `prepare` fails closed (`N01-stale-source`,
  manual-run attempts 2 and 4); the 86400 cap exists in the contract but is not used for the series.
- A cold GEX computation can take more than two minutes (`GALECORE_TIMEOUT_SECONDS`).
- Semantic entailment of prose is not verified; only paths, numbers, signs, the skew semaphore and
  directive patterns are.
- GEX history and macro/ValidationLayer facts are out of scope (need GaleCore work; owner decisions
  D-1 / D-2 in the work item).
